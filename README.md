# SamoletPay

Платформа для компаний, которые работают с самозанятыми, ИП, физлицами и штатными сотрудниками. Что внутри:
- электронные договоры и акты, кадровый ЭДО (КЭДО);
- проверка статуса НПД и риск-контроль;
- массовые выплаты с чеками;
- биржа заданий, подбор персонала, сплит-платежи;
- Open API;
- кабинет оператора платформы.

Анализ конкурента, улучшения и варианты названия: [docs/ANALYSIS.md](docs/ANALYSIS.md).

## Запуск

Нужен Node.js 22.5+, внешних зависимостей нет (встроенный `node:sqlite`, собственный генератор PDF).

```bash
npm start          # http://localhost:3000
npm test           # 20 модульных тестов
```

Демо-доступы (создаются при первом запуске):

| Роль | Email | Пароль |

| Компания — владелец | demo@samoletpay.ru | demo1234 |

Боевой запуск: скопируйте `.env.example` и задайте переменные. Обязательно `DEMO_MODE=0`, `SEED=0`, `COOKIE_SECURE=1`, `APP_URL`, провайдеры SMS и email. Деплой на VPS (Oracle Cloud + Cloudflare Tunnel): [deploy/DEPLOY.md](deploy/DEPLOY.md). Docker: `docker build -t payout . && docker run --env-file .env -p 3000:3000 -v payout:/data payout`.

## Архитектура

```
server/
  index.js      — HTTP-сервер, заголовки безопасности (CSP, HSTS), статика, плавная остановка
  http.js       — роутер: авторизация, роли, лимиты частоты, CSRF
  db.js         — схема SQLite, деньги в копейках, триггеры неизменности подписанных документов
  security.js   — пароли (scrypt), сессии (в БД только хеш), TOTP 2FA, лимиты, API-ключи (хеш), HMAC, права ролей, журнал
  jobs.js       — персистентная очередь задач: повторы, защита от дублей, восстановление после падения
  services.js   — выплаты (адаптер банка, возвраты), сплит, вебхуки, регламентные задачи
  logic.js      — тарифы, расчёт налогов и комиссий, риск-проверки, шаблоны документов (включая КЭДО)
  mailer.js     — исходящие письма и SMS (sms.ru, Unisender Go или журнал)
  pdf.js        — PDF с кириллицей (встраивание TrueType), штампы подписей, SHA-256
  routes/       — auth, public, company, contractors (+сотрудники), documents (+шаблоны), payouts, work (биржа, подбор, сплит), person (кабинет физлица), api_v1, admin, pages
public/         — сайт и SPA-кабинеты (компания, исполнитель/сотрудник, оператор)
tests/          — unit.test.js (node:test), e2e.js и e2e2.js (Playwright)
```

## Безопасность
- **Пароли:** хешируются scrypt; минимум 8 символов, обязательно буквы и цифры. Восстановление по ссылке из письма; после сброса — выход на всех устройствах.
- **2FA:** TOTP, работает с Google Authenticator и Яндекс Ключом.
- **Сессии:** срок жизни 14 дней, список активных устройств, выход везде. В БД хранится только хеш токена.
- **Лимиты частоты:**
  - вход — 10 попыток за 15 минут;
  - код подписи — 5 попыток на код;
  - регистрация, восстановление пароля, публичная проверка НПД, заявки — тоже ограничены;
  - API — 600 запросов в минуту.
- **Роли команды:**
  - **владелец** — всё;
  - **бухгалтер** — выплаты, подпись, баланс, выгрузки, журнал;
  - **менеджер** — готовит документы и черновики выплат, но не отправляет деньги и не подписывает.
- **API-ключи** хранятся только в виде SHA-256.
- **Вебхуки** подписываются HMAC-SHA256: заголовки `X-SamoletPay-Timestamp` и `X-SamoletPay-Signature`.
- **Защита от атак:** CSRF (проверка Origin), CSP, X-Frame-Options, защита от CSV-инъекций в выгрузках, экранирование всех данных в документах.
- **Журнал действий** всех значимых операций; записи нельзя удалить.

## Надёжность
- **Деньги** хранятся в копейках (INTEGER). Баланс не может стать отрицательным (CHECK на уровне БД).
- **Выплаты** проходят через очередь в БД: переживают перезапуск сервера, повторяются при сбое банка. Если попытки исчерпаны, деньги автоматически возвращаются, причём ровно один раз.
- **Idempotency-Key** в Open API защищает от двойных выплат при повторной отправке запроса.
- **Ежедневные задачи:** резервная копия БД (`VACUUM INTO`, последние 7 копий), перепроверка статусов НПД, чистка истёкших сессий.
- **Мониторинг:** `/healthz`; структурные логи (`LOG_REQUESTS=1`).

## Функции

| Модуль | Что умеет |
|---|---|
| Исполнители | НПД, ИП, ГПХ, ЕАЭС; импорт CSV; проверка НПД; риск-профиль; лимит 2,4 млн ₽; бывшие сотрудники (запрет на 2 года); повторное приглашение |
| Документы | Встроенные и собственные шаблоны с подстановками; пакетное создание и подпись; PDF; публичная проверка подлинности `/verify/<sha256>`; подписанные документы нельзя изменить или удалить |
| КЭДО | Сотрудники; согласие на КЭДО — обязательный первый документ (ст. 22.1 ТК РФ); трудовой договор, приказы, листы ознакомления |
| Выплаты | Разовые и реестры; превью рисков; черновики; повторная проверка НПД перед перечислением; чеки; выгрузка в 1С |
| Биржа | Отклики → договор и задание → сдача → акт и выплата |
| Подбор | Заявки компаний; оператор добавляет кандидатов, компания сразу видит их с договором |
| Сплит | Ссылка на оплату → распределение по долям в копейках, агентское вознаграждение |
| Уведомления | В кабинете, SMS и email исполнителям, письма бухгалтерии о проведённых выплатах |
| Оператор | Заявки с сайта, подбор, компании (тариф, блокировка), подтверждение поступлений, журнал SMS и писем, очередь задач, общий журнал |

## Что подключить перед боевым запуском

| Что | Где в коде | Статус |
|---|---|---|
| API банка для выплат | `services.js` → `bank.transfer` | адаптер-заглушка (демо) |
| Автоматическая сверка выписки | `routes/admin.js` (сейчас ручное подтверждение) | ручной режим готов |
| API «Мой налог» для чеков | `services.js` → обработчик `payout.process` | чеки генерируются локально |
| SMS и email | `.env`: `SMS_PROVIDER`, `EMAIL_PROVIDER` | готово, нужны ключи |
| Эквайринг для сплита | `routes/public.js` → оплата сплита | демо-форма |
| Госключ | `sign_method=gosklyuch` | интерфейс готов, нужен договор с Минцифры |
| PostgreSQL | `db.js` | SQLite с WAL; для нескольких серверов нужен драйвер `pg`, его нельзя было установить в этой среде |
